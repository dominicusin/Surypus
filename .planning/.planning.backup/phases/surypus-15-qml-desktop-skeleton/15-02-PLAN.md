<task type="auto">
  <name>Task 1: Create ApiClient.qml singleton</name>
  <files>
    qml/api/ApiClient.qml
    qml/api/qmldir
  </files>
  <read_first>
    QRestAccessManager in Qt 6.7+:
    - C++ class `QRestAccessManager` is part of `QtCore` module
    - In QML, it can be accessed via `Qt.restAccessManager()` or by creating a C++ wrapper that exposes it to QML as a singleton
    - Alternative: Create a C++ helper class that wraps QRestAccessManager and register it as a QML singleton type

    Since QRestAccessManager is primarily a C++ class (not directly exposed to QML in Qt 6.7), the approach is:
    1. Create a small C++ wrapper class `SurypusApiClient` in `api/surypusapiclient.h/.cpp` that wraps `QRestAccessManager` and exposes QML-friendly signals/slots
    2. Register it as a QML singleton in main.cpp

    OR simpler approach for this phase:
    Since QRestAccessManager's QML API may not be fully mature in Qt 6.7 (was Tech Preview), use a C++ helper registered as QML singleton. This is the recommended pattern from the research docs (Pattern 2).

    The ApiClient must:
    - Store base URL (`http://localhost:3000/api/v1`)
    - Store auth token after login
    - Provide `login(username, password)` — POSTs to `/login` with JSON body, stores returned token
    - Provide `get(path)`, `post(path, jsonBody)`, `put(path, jsonBody)`, `del(path)` — all inject `Authorization: Bearer <token>` header
    - Emit signals: `loginSucceeded(token)`, `loginFailed(errorMsg)`, `requestFailed(path, status, error)`
    - Parse JSON responses automatically
  </read_first>
  <action>
    Create two files:

    **File 1: `qml/api/surypusapiclient.h` and `qml/api/surypusapiclient.cpp`**
    
    C++ class `SurypusApiClient` inheriting `QObject`:
    - Private member: `QRestAccessManager *m_manager`, `QString m_baseUrl`, `QString m_authToken`
    - Public Q_INVOKABLE methods:
      - `void login(const QString &username, const QString &password)` — POSTs JSON to baseUrl+/login
      - `void get(const QString &path)` — GET request with auth header
      - `void post(const QString &path, const QJsonObject &body)` — POST with auth header
      - `void put(const QString &path, const QJsonObject &body)` — PUT with auth header
      - `void del(const QString &path)` — DELETE with auth header
      - `void setBaseUrl(const QString &url)` — set API base URL
      - `QString authToken() const` — getter for current token
    - Signals:
      - `void loginSucceeded(const QString &token)`
      - `void loginFailed(const QString &error)`
      - `void requestSucceeded(const QString &path, const QJsonDocument &response)`
      - `void requestFailed(const QString &path, int statusCode, const QString &error)`
    - Use `QNetworkRequestFactory` to set base URL once
    - On login success: store token in `m_authToken`, emit `loginSucceeded`
    - On each request: set `Authorization: Bearer <token>` header

    **File 2: `qml/api/qmldir`**
    ```
    singleton ApiClient 1.0 SurypusApiClient
    ```

    **Register in main.cpp**: Add `qmlRegisterSingletonType<SurypusApiClient>("SurypusApiClient", 1, 0, "ApiClient", ...)` before engine.load().
  </action>
