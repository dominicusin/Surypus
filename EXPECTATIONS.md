# Expectations for Contributors and Maintainers

This document outlines mutual expectations between contributors and maintainers.

## What You Can Expect from Maintainers

### Response Times

| Type | Expected Response |
|------|-------------------|
| Security issues | Within 24 hours |
| Critical bugs | Within 48 hours |
| Bug reports | Within 48 hours |
| Feature requests | Within 1 week |
| Pull requests | Within 48 hours |
| Questions | Within 1 week |

### Our Commitments

- **Treat everyone with respect** - No question is too basic
- **Provide constructive feedback** - We explain the "why" behind decisions
- **Be transparent** - Document decisions and reasoning
- **Give credit** - Recognize all contributions
- **Maintain quality** - Uphold project standards consistently

### Availability

- **Regular hours**: We maintain this project during business hours (UTC+3)
- **Response time**: Within 48 hours on business days
- **Breaks**: We may take breaks and will announce them

## What Maintainers Expect from Contributors

### Before Contributing

- Read [CONTRIBUTING.md](CONTRIBUTING.md) and this document
- Search existing issues to avoid duplicates
- Check if your contribution aligns with the [Vision](VISION.md)

### Quality Standards

- Follow the project's coding style
- Write tests for new functionality
- Update documentation
- Keep changes focused and atomic

### Communication

- Be respectful and constructive
- Explain your reasoning
- Accept feedback gracefully
- Be patient - maintainers are volunteers

## Contribution Requirements

### Pull Requests

- Fill out the PR template completely
- Reference related issues
- Ensure CI checks pass
- Respond to review feedback within 7 days

### Issues

- Use the provided templates
- Include steps to reproduce (for bugs)
- Provide environment details
- Be specific about expected behavior

## Enforcement

### Code of Conduct

All participants must follow the [Code of Conduct](CODE_OF_CONDUCT.md). Violations will be addressed according to the enforcement guide.

### Maintaining Standards

Maintainers may:
- Request changes to contributions
- Close issues that don't follow templates
- Decline contributions that don't align with project vision
- Ban participants who violate the Code of Conduct

## Disagreeing with Maintainers

If you disagree with a decision:

1. **Ask for clarification** - There may be context you're missing
2. **Explain your perspective** - Provide reasoning and alternatives
3. **Accept the decision** - Maintainers have final say on project direction
4. **Fork if needed** - You're welcome to create your own fork

## Recognition

### How We Recognize Contributions

- **Release notes** - Significant contributions mentioned
- **Contributors page** - All contributors listed
- **Shoutouts** - Regular thanks on social media
- **Badges** - Contributors receive GitHub profile badges

### Types of Contributions We Value

- Code (bug fixes, features, performance)
- Documentation (guides, tutorials, translations)
- Testing (writing tests, reporting bugs)
- Design (UI/UX, graphics, logos)
- Community (answering questions, mentoring)
- Donations (financial support)
