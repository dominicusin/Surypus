# Surypus Launch Checklist

Congratulations on starting your open source journey! This checklist
will guide you through a successful launch.

## Documentation

Before launch, ensure these files exist:

- [ ] `LICENSE` - Open source license (MPL-2.0)
- [ ] `README.md` - Project overview and quick start
- [ ] `CONTRIBUTING.md` - Contribution guidelines
- [ ] `CODE_OF_CONDUCT.md` - Community standards
- [ ] `SECURITY.md` - Security policy

## Name & Branding

- [ ] Name is memorable and descriptive
- [ ] No conflicts with existing projects
- [ ] No trademark conflicts
- [ ] GitHub account created for the project
- [ ] Website/Twitter/LinkedIn accounts reserved (if applicable)

## Code Quality

- [ ] Code follows consistent style guidelines
- [ ] Functions/methods/variables have clear names
- [ ] Code is well-commented
- [ ] No sensitive data in git history (passwords, keys, etc.)

## Community Ready

- [ ] Issue templates created (bug_report.yml, feature_request.yml)
- [ ] PR template created (pull_request_template.md)
- [ ] Labels created for issues/PRs
- [ ] Discussion templates created (idea.yml, question.yml)
- [ ] Milestones created (v2.0, v3.0, etc.)

## Legal

### Individual Contributors

- [ ] Checked with legal department (if employed)
- [ ] Understand IP and open source policies

### Company/Organization

- [ ] Spoken with legal department
- [ ] Marketing plan for launch
- [ ] Community manager designated
- [ ] At least 2 people with admin access
- [ ] Trademark review completed

## Technical

- [ ] CI/CD pipelines configured
- [ ] Security scanning enabled
- [ ] Dependency scanning enabled
- [ ] Branch protection rules set
- [ ] README badge enabled

## Launch Day

- [ ] README reviewed and polished
- [ ] CONTRIBUTING reviewed and polished
- [ ] CODE_OF_CONDUCT reviewed and polished
- [ ] SECURITY policy in place
- [ ] First release planned

---

*Use this checklist before your first public release.*
